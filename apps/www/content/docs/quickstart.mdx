---
title: Quickstart
description: Run Pinwren with Docker, create a project and see your first pinned comment in about five minutes.
---

You need Docker with Compose. The stack is two containers: Pinwren and Postgres 17.

<Steps>
<Step>

### Get the compose file and set three values

```bash
git clone https://github.com/Krithik-m-codes/pinwren.git && cd pinwren
cp docker/.env.example docker/.env
```

Open `docker/.env` and fill in the three required values:

```bash title="docker/.env"
# The URL people open and the widget calls. No trailing slash.
PINWREN_URL=http://localhost:3000
# openssl rand -base64 48
PINWREN_SECRET=<a long random string, at least 32 characters>
# openssl rand -hex 24
POSTGRES_PASSWORD=<another random string>
```

`http://localhost:3000` is fine for a first try on your own machine. For a real install use your public HTTPS
URL, e.g. `https://feedback.example.com`, behind a [reverse proxy](/docs/self-hosting/reverse-proxy).

</Step>
<Step>

### Start it

<Tabs items={["Published image", "Build from source"]}>
<Tab value="Published image">

Each release publishes a multi-arch image (amd64, arm64). Pin a version in `docker/.env` and start without
`--build`:

```bash title="docker/.env"
PINWREN_IMAGE=ghcr.io/krithik-m-codes/pinwren:0.1.0
```

```bash
docker compose -f docker/compose.yml --env-file docker/.env up -d
```

</Tab>
<Tab value="Build from source">

```bash
docker compose -f docker/compose.yml --env-file docker/.env up -d --build
```

</Tab>
</Tabs>

Database migrations run automatically when the app starts. Check it is up:

```bash
curl http://localhost:3000/api/health
# {"ok":true,"version":"0.1.0"}
```

</Step>
<Step>

### Create your account and first project

Open `PINWREN_URL` and create the first account. **The first account on a new server is its instance
admin**, so email, security and licence settings are open to you straight away — there is no setup token to
find in the logs. (Keep the server private until you have signed up; the compose file only listens on
`127.0.0.1`.) The setup screen then asks for a **workspace name**, a **first project**, your **website
domain** — the project's first allowed site — and what the site is for: a **public website** keeps bug
reports private, a **staging or client review** site shows reviewers each other's pins.

<Callout title="Sign-up is closed after the first account">
  Anyone else needs an invitation from **Settings › Users**. To let anyone sign up, set
  `PINWREN_DISABLE_SIGNUP=false` in `docker/.env` and restart.
</Callout>

</Step>
<Step>

### Set up email

Open **Settings › Email**, enter your SMTP server (host, port, security, user, password and from address) and
click **Send test email**. From then on every new report is emailed to the team, and reporters who left an
address get a confirmation and updates. See [Email](/docs/integrations/email) for provider settings.

</Step>
<Step>

### Allow your site

In the project's **Install** tab, under **Allowed sites**, list every hostname that will load the widget, for
example `www.example.com`, `*.staging.example.com` or `localhost:5173`. Requests from any other origin are
refused with `403 ORIGIN_NOT_ALLOWED`, and the tab lists them — "Blocked a request from https://… 2 min ago" —
with an **Allow** button. It also has a tester that tells you whether a URL is allowed.

</Step>
<Step>

### Paste the snippet

Copy the snippet from the **Install** tab and add it before `</body>` on every page:

```html title="index.html"
<script src="https://feedback.example.com/widget.js" data-project="pk_…" async></script>
```

The project key is public by design — it only works from your allowed sites. The Install tab also has
Next.js, Google Tag Manager, npm and React versions, all prefilled with your key and server address, and a
`npx @pinwren/cli doctor` command that checks the setup from your terminal.

</Step>
<Step>

### Leave a pin

Reload your site. The launcher appears in the bottom-right corner, and the Install tab switches from
**Waiting for your site** to **Connected**. Press <kbd>C</kbd> (or open the launcher and choose comment),
click an element, write a comment and send it. It appears in the dashboard inbox straight away. Report a bug
the same way and the team gets an email with the screenshot, page, browser and a link. A checklist on the inbox
tracks these first steps until they are all done.

</Step>
</Steps>

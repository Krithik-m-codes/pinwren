---
title: Configuration
description: Every widget, capture and branding option, its default, and where it is set.
---

Widget settings live **per project on the server**, not in your snippet. You change them in the dashboard
(project › Widget), they are stored in the database, and the widget fetches them on every page load from
`GET /w/config`. A change reaches every page that embeds the project at the next load — no redeploy.

The server always sends every key with its default filled in, and the widget validates each value again
before using it: an unknown or malformed value falls back to its default instead of breaking the page.

```json title="GET /w/config (abridged)"
{
  "project": { "name": "Marketing site", "slug": "marketing-site", "publicRead": true },
  "widget": {
    "launcher": { "position": "bottom-right", "accent": "#5b5bd6" },
    "modes": { "comment": true, "bug": true }
  },
  "capture": { "console": "warnings", "network": "failures" },
  "branding": { "hidePoweredBy": false, "dialogAccent": null, "logoUrl": null }
}
```

On the page itself you can only override the launcher colour (`data-accent` or the `accent` init option) and
the language (`data-locale` / `locale`) — see [Install](/docs/widget#script-attributes).

The project's **public read** switch (`publicRead`, on by default) decides whether visitors see existing
feedback at all. When it is off, the widget shows no pins, no “View comments” entry and no side panel —
people can still send feedback.

See [Panel actions](/docs/widget/panel-actions) and [Privacy & masking](/docs/widget/privacy) for those two
settings in detail.

<NewIn>
  `hidePoweredBy` only takes effect with an Enterprise licence that has the `white_label` entitlement; without
  one, the setting is kept but `/w/config` sends `false`. It is the only gated setting — see [Editions &
  licensing](/docs/licensing).

<Callout type="info" title="Privacy mode changes what the server sends">
  With `privacyMode` on, `/w/config` always returns `consent.enabled: true` and caps `capture.console` at
  `"errors"`, whatever is stored. Team-only and webhook panel actions are never sent to the page.
</Callout>

## Limits enforced by the server

| Limit                      | Value                                                                                          |
| -------------------------- | ---------------------------------------------------------------------------------------------- |
| Reports and replies per IP | 10 per minute per project by default (`WIDGET_RATE_LIMIT_PER_MIN`, or the project's own limit) |
| Comment body               | 10,000 characters                                                                              |
| Screenshot                 | PNG, JPEG or WebP data URL                                                                     |
| Attachments                | 3 files, 5 MB each, PNG, JPEG, WebP, GIF or PDF                                                |
| Pins returned for a page   | 100 most recent open items                                                                     |

Over the rate limit the API answers `429 RATE_LIMITED`; the widget shows the message and keeps bug reports in
its [offline outbox](/docs/widget/bug-reports#offline-outbox).
